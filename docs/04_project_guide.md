# プロジェクトガイド（第5回〜第14回）

基礎演習で手に入れた道具を組み合わせて，**社会課題を解決するプロジェクト** をチームで企画・実装・発表します．
評価で重視するのは「難しい技術を使ったか」ではなく，**誰の・どんな課題を・どのデータと方法で・どこまで解決できたか（できなかったか）を筋道立てて示せたか** です．

## 進め方

| 回 | やること | 成果物 |
|---|---|---|
| 第5回 | 課題の洗い出し，テーマ候補のディスカッション，**データの下見**（候補の話題でどんなデータがどれだけ集まるかを小さく確認） | 企画シート（下書き） |
| 第6回 | テーマ決定，データ取得計画，役割分担，最小構成（MVP）の定義 | [企画シート](../project/planning_sheet.md)（完成） |
| 第7回 | **冒頭に企画発表（1班 10 分）**と教員からのフィードバック．その後，データ取得・制作を開始 | 企画スライド |
| 第8〜11回 | 実装・分析・改善（毎回「今週できたこと・困っていること」を報告） | 動くもの，図，中間結果 |
| 第12回 | 実装の締め．結果の整理，考察，発表資料の作成 | 発表資料（下書き） |
| 第13回 | 発表練習（時間計測，質疑の想定） | 発表資料（完成） |
| 第14回 | 合同プレゼンテーション会 | 発表・質疑 |

## 良いテーマの条件

1. **困っている人が具体的**：「地域の人」ではなく「駅前の駐輪場を管理している市の職員」「一人暮らしを始めた大学1年生」．
2. **データで見える化できる**：カメラで数えられる／SNS で実際に語られている．**取れるかどうかは思い込まず，下見で確かめる**（後述）．
3. **3週間で最小構成が動く**：まず小さく作って動かし，余った時間で広げる（逆はできない）．
4. **結果が行動につながる**：「〇〇が分かった」の先に「だから△△すればよい」がある．
5. **倫理的に問題がない**：撮影の同意，投稿者の匿名化，センシティブな属性の推定をしない．

### テーマの見つけ方（第5回のディスカッション用）

- **身の回りの不便から**：通学路，食堂，図書館，バイト先，サークル，実家の地域で「数えられたら／分かったら助かること」．
- **ニュースから**：災害，交通事故，ゴミ，観光公害，熱中症，物価，孤立．SNS で語られていることを確かめる．
- **昨年度の例から**：ゴミ分類モデル（万博のゴミ分別の負担 → カメラで種類を判定），自転車の危険運転検知（事故と取り締まりコスト → ヘルメット未着用の検出と場所・時間帯の可視化）．

## データの下見（企画を決める前に必ず行う）

**特に SNS 分析では，Bluesky の日本語投稿は X（旧Twitter）より少なく，話題によってはデータが集まらない・ニュース転載や bot に偏る・定型投稿ばかり，ということがよくあります**（うまくいく話題もあります）．「分析したい」と「データがある」は別なので，テーマを決める前に候補の話題を **小さく取得して量と質を確認** してください．

| テーマ | 下見の方法 | 確認すること |
|---|---|---|
| SNS分析 | 第2回 Notebook 11 節の `preview_queries([候補1, 候補2, ...])`（候補ごとに 300 件取得して指標を表にする） | 1日あたりの件数，投稿者の偏り（最多投稿者の占有率），リンク付き（ニュース転載）の割合，重複本文の割合，本文の長さ |
| 画像認識 | 想定する場所・時間帯で 5〜10 分撮影し，第3回 Notebook の手順で検出を試す | 対象が映る頻度，検出できるか（距離・明るさ・遮蔽），撮影の許可が取れるか |

下見の結果の見方（SNS）：

- **量が十分（目安：1日 50 件以上）で，投稿者が分散している** → そのまま進める．
- **量が少ない** → 同義語を足す，期間を長く取る，英語圏も含める（`04_english_analysis.ipynb`），自治体・報道機関など公式アカウントの投稿や返信を使う．
- **ニュース転載・bot・定型投稿が多い** → それらを除外して再確認する．除外すると残らないなら，問いを「公式発信の内容と反応」「英語圏との比較」「特定アカウントへの返信の分析」のような，**データがある形** に変える．
- **どうしても集まらない** → テーマを変える．下見で「無い」と分かることも成果であり，企画発表で理由とともに説明してよい．

下見の結果（検索語，件数／日，質のメモ，採否）は企画シートに記入し，企画発表で示します．

## 最小構成（MVP）の考え方

| テーマ | 最小構成の例 | 広げ方 |
|---|---|---|
| 画像認識 | 学習済み YOLO の `person`/`car` などで対象を数えて CSV → グラフ | 独自クラスを学習，複数地点，リアルタイム通知，Web 画面 |
| SNS分析 | 下見で量・質を確かめた 1 つの検索語を 1〜2 週間分取得 → 頻出語と推移 → 100 件に手でラベル → 分類器で割合を出す | 比較条件を増やす，返信の分析，感情分析（学習済みモデル），英語圏との比較（世界情勢） |

## 企画発表（第7回冒頭，1班 10 分＋質疑）

第7回の冒頭に，全班が 10 分ずつ企画を発表します．スライド 6〜8 枚が目安です．

| # | 内容 | 目安 |
|---|---|---|
| 1 | チーム名・メンバー・テーマ | 0.5 分 |
| 2 | 社会課題：誰が，何に困っているか，なぜ問題か（数字・ニュースで裏付け） | 2 分 |
| 3 | 提案：何を作る／何を明らかにすると，その困りごとがどう減るか | 1.5 分 |
| 4 | **データの下見の結果**：どのデータを，どれだけ，どんな質で集められたか（表・図で） | 2 分 |
| 5 | 方法：演習の道具をどう組み合わせるか（取得 → 加工 → 機械学習 → 見せ方） | 1.5 分 |
| 6 | 最小構成（第9回までに動かすもの）と発展 | 1 分 |
| 7 | 役割分担・スケジュール・想定される難しさ | 1 分 |
| 8 | 教員からのフィードバック（質疑） | 3〜5 分 |

発表後のフィードバックを受けて，企画シートを修正してから制作に入ります．

## 毎週の進捗報告（第8〜11回，各チーム3分）

1. 今週できたこと（動いたもの・図を1枚見せる）
2. 分かったこと・意外だったこと
3. 困っていること（技術，データ，チーム）
4. 来週までにやること（担当者付き）

## 役割分担の例（5名）

| 役割 | 主な仕事 |
|---|---|
| リーダー（3年） | 進捗管理，教員との窓口，発表の全体構成 |
| データ担当 | 撮影・取得計画，データの下見と品質確認，倫理面の確認 |
| 実装担当（2名） | Notebook → `.py` 化，モデル学習，検出・分析コード |
| 分析・発表担当 | 図表作成，考察，スライド，発表練習の進行 |

役割は固定せず，**全員が自分のチームのコードと結果を説明できる** ようにしてください（質疑で誰にでも当たります）．

## 提出物

提出するのは **発表スライド（pptx）のみ** です．コードやデータの提出は求めません．

- 企画発表（第7回）：企画スライド（pptx）
- 最終発表（第14回）：発表スライド（pptx）．構成は [発表テンプレート](../project/presentation_template.md) を参照
- スライドには，データの取得条件（検索語・期間・件数／撮影場所・時間・枚数），手法，結果の数値，限界を含めること（質疑で確認します）
- 個人が特定できる情報（顔，ハンドル名，投稿 URL）は載せない

## 評価の観点（シラバスに基づく）

| 観点 | 見るところ |
|---|---|
| 知識・技能 | 演習の道具を正しく使えているか．手法の選択理由と限界を説明できるか |
| 思考力・判断力・表現力 | 問い → データ → 方法 → 結果 → 考察が一直線につながっているか．図が主張を支えているか |
| 主体的な態度 | 毎週の進捗，役割の遂行，チーム内の相互支援，質疑への対応 |

## データ倫理チェックリスト（企画時と発表前に確認）

- [ ] 撮影する人・場所の許可を得た（学内は教員に相談）
- [ ] 映像・投稿データは授業外に持ち出さない．クラウドや GitHub に上げない
- [ ] 発表資料に個人が特定できる顔・ハンドル名・投稿 URL を載せない（必要なら加工・匿名化）
- [ ] 投稿者の性別・年齢・病歴などセンシティブな属性を推定・分類していない
- [ ] 結果の限界（標本の偏り，データ量，精度，因果ではないこと）を発表で述べる
